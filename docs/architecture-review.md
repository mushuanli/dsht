## 本轮实施

### 1. 前台调度的生命周期与边界

将调度从应用门面提取为 `src/controller/foreground.ts` 的 `ForegroundSlot`，
只接收状态发布和跟踪回调，不持有 Controller、会话或连接对象。

新增回归在修改前证实：停止时没有取消占用者、旧异步上下文可以借用新占用者、
取消后仍可派发嵌套工作、同步发布观察者可以抢在排队者前面，以及 UI 快照泄漏 AbortController。
修复后按具体操作 ID 判断嵌套所有权，关闭入口并取消占用者，交接时先保留名额再通知观察者，
只向 UI 提供不可变的显示快照。

取消保持协作式：已开始的工作可返回自己的结果或异常，调度器不伪造远程取消成功。
取消之后新的嵌套工作不会开始，等待者在停机时被释放；不强制等待不响应信号的任意外部闭包。

### 2. 列表刷新与页面导航分离

`SessionController.refreshLists()` 只更新数据；`showPicker()` 明确切换页面。
`restoreSelectedSession()` 重建订阅但不改变页面和 all 筛选。
`Controller.ready()` 仅首次应用启动目录和 initialSession；后续连接恢复操作员的当前选择。

原 trace 测试记录了“chat → workspaces → sessions、s1 → none”的缺陷，现在要求重连不产生这些导航变化。
新增集成测试覆盖选择器背后的订阅恢复，以及离开启动会话后重连不能重新打开它。
路径输入页面也保持原 screen。

### 3. 断线期间保留编辑能力

TextInput 的焦点不再取决于 online。用户可继续写草稿、操作本地提示词，
联网操作在控制器层明确拒绝并保留输入；重新连上不会自动提交草稿。
提示词增删改重新使用本地操作入口，错误仍由应用统一发布。
控制器与实际 Ink 输入测试分别覆盖离线本地操作、联网拒绝和重连后的草稿保留。

### 4. Loop 运行所有权与退出清理

第二轮从当前工作树继续，前一轮属于已验证的实质进展。
`src/controller/loop-coordinator.ts` 接管 Loop 编排，应用门面由 1,848 行降至 1,289 行。
`LoopHost` 只提供会话事实、回复文本、发送、状态发布与跟踪能力；不传递 Controller、State 或 Transcript。
协调器选择当前运行，内部每个 `LoopExecution` 独占其验证标志、截止与提交定时器、待发送内容和迟到回调。
纯评分规则继续留在 `ScoredLoop`，没有把 I/O 混进状态机。

修改前两个新增集成用例分别证明：停止客户端没有取消在飞验证；旧验证完成会清掉新运行的验证标志，
导致重复 idle 帧再启动第三个验证。拆分后两者均修复。
额外回归覆盖旧发送请求失败不能污染新运行、重连快照未就绪时保留下一步、
发布验证状态时同步停止不能继续启动验证器，以及产出物读取异常不会产生未处理的 Promise 拒绝。
读取异常保留原有“本机访问边界不推翻已有 verdict”的语义，并显示检查不可用的说明。

真实 ProcessVerifier 与 Controller 的组合测试又证明取消分支原先可能早于宿主取消确认就返回。
现在验证器通过 `settle()` 暴露自身清理完成点，控制器等它收尾后才关闭连接；
取消走 session control lane，不受前台忙碌或前台关闭阻挡。CLI 检查布尔结果，取消被拒绝时不能报告确认成功。
取消确认仍最多等待 1 秒，子进程仍使用既有的 SIGTERM/SIGKILL 机制；纯内存验证适配器不必实现清理能力。

### 5. 输入版本与延迟命令的所有权

第三轮提取 `ui/input/use-composer.ts`，负责草稿、光标、临时编辑意图及待答期间的寄存草稿。
通过普通回调访问会话身份、回填重置和通知，不导入 Controller 或会话内部对象。
异步提交持有会话与草稿修订号，完成时只消费仍属于该提交的草稿；
读者清空后重新输入相同文字也算新草稿。切换会话会释放编辑与寄存状态。
同一临时编辑意图只允许一个保存操作在飞，保存期间继续输入则保留编辑模式，供下次显式提交。
Esc 和会话切换后的迟到结果不能擦除新内容，也不能恢复旧编辑状态。
新增三个真实 Ink 测试在修改前分别复现继续输入被清空、Esc 后新草稿被清空和重复保存。
另有回归覆盖切换会话及文本相同但版本更新的草稿。

`ui/input/use-deferred-lines.ts` 独立持有已接受命令的 FIFO 与执行状态。
修改前的重连测试证明：前台占用者在离线时结束，会让队列取出命令，再因离线拒绝而丢失。
现在等待 online、连接基线与会话快照就绪，并在每次执行前重新授权；换会话丢弃旧会话的等待项。
每条命令完成后才派发下一条，既有管线与键盘路由继续由 App 统一组装。
本地等待队列只容纳用户已按 Enter 提交且策略要求等待的命令；不自动提交未发送草稿，
也不复制宿主 `session/control` 的消息队列。
App 从 1,204 行降至 1,133 行；面板、历史控制和只读查询边界仍待拆分。

### 6. 面板状态归属与历史回填

第四轮将面板状态和键盘占用表集中到 `ui/dialogs/use-panels.ts`。
组合根继续决定按键优先级与执行命令效果，hook 负责打开、关闭、保留指定面板和会话重置。
临时表单、队列、搜索与历史查询共用同一份状态；peek 仍由应用持有，UI 只读其开关并调用关闭能力。
删除 SessionInfo 中的 UI 类型及会话控制器的未用导入。
共享契约只定义 `ModelState`、`HistoryPanel`、`SearchPanel` 数据，不再转出 UI 可见性状态。
App 现为 1,049 行，历史视口与异步跳转仍留在组合根，不能因此宣称 UI 拆分已全部完成。

新增按键回归证明：原先懒回填的异步闭包返回 void，调用处却按布尔值判断，
导致一次向上键只取回历史、不把找到的提示词放入输入框。`use-history-recall.ts` 现在明确返回是否找到内容，
保持最多 20 页的扫描界限，并通过草稿修订号恢复输入；继续编辑、切换会话或卸载后的旧结果不能移动新草稿的回填游标。
同时考虑后台回填已插入相同提示词的情况，不能仅按当前翻页是否新增索引项判断。
四个实际 Ink 回归覆盖首次按键、翻页期间继续编辑、后台索引插入以及 Esc 取消。
测试等待初始后台回填完成，再构造被淘汰的索引前缀，避免把测试准备与初始化竞争混在一起。

### 7. Catalog 边界、共享扫描与启动取消

第五轮删除 Catalog 对 ControllerStore 的依赖，以 `CatalogHost` 只提供主机访问、
选择修订号/会话身份和 `CatalogUpdate` 元数据发布。架构检查禁止 catalog 导入 state.ts。
模型读取与选择接收前台信号；后台模型与 preset 请求接收连接寿命及 Catalog 代际信号。
reset/close 使旧请求失效，同一 Client 返回的迟到响应也不能回写；重复刷新取消上一次读取。
所有请求纳入 settle，客户端停止先取消 Catalog 再等连接清理。
四个回归在修改前证明模型读取/选择未取消、重置后旧模型/preset 仍回写。
完整回归又检查到首次模型刷新早于 online 发布，调整初始化顺序后保留无 control stream 宿主的默认模型显示。
取消本机请求不等于撤销已经抵达宿主的模型设置；客户端只停止等待和本地结果发布。

成本扫描先拒绝已取消的调用者，避免其加入或取消一个有效的共享扫描；
已加入的调用者随后取消，仍按原有约定取消整次共享扫描，且不取消远端 agent 回合。
stop 主动中止扫描后再等待，保留已完成的账本写入。先登记共享任务再发布扫描状态，
同步观察者可安全加入或停止它，不会创建第二次扫描；预取消历史读取不再打开订阅。
账本写入结束也检查取消，不把中途取消的扫描记录成完整成功。

CLI 的连接/快照等待、命令排队等待、回合/Loop 等待及 verdict 宽限等待均使用客户端寿命信号。
停止不再留下等待定时器；提示词动作返回 false 时即时报告拒绝，而不是成功退出或继续等一个不存在的回合。
三个新增启动测试分别复现发送拒绝被忽略、停机后回合等待继续运行，以及已停止客户端仍等待连接。

### 8. Session 状态边界与历史请求所有权

第六轮将会话状态契约放入 `session/state.ts`：应用 State 组合它，SessionController 不再反向导入应用 State。
SessionStore 只允许发布导航、列表和会话状态；online、pending、SessionInfo 引用由应用/连接持有，
会话动作没有覆盖这些字段、模型元数据或 shell 快照的类型能力。preset 名单作为显示标签解析的显式参数传入。
架构检查禁止 session 导入根 state.ts，防止以后重新扩大依赖。
这仍是类型和能力边界，SessionInfo/Transcript 的公开可变对象尚未迁移为只读显示快照。

`session/history-reader.ts` 独立负责快照等待、翻页、搜索、定位窗口和前缀加载。
HistoryHost 仅提供所选会话身份/修订号/记录、传输、目标归属检查与刷新通知；没有导航或通用状态写入能力。
每个任务登记自己的取消器和读取目标，切换会话/断线取消全部读取，关闭历史窗口只取消该窗口的翻页。
停止时等待历史任务收尾；临时搜索记录及时释放，已取消或失去归属的定位结果在交还调用者前释放。
单页读取也拒绝无进展的分页，不再把异常页留给外层循环才判断。

四个新增回归在修改前分别证明：已取消的快照等待和前缀读取仍返回成功、
关闭的历史窗口被迟到页面重新填充、换会话没有取消旧搜索请求。
修复后保留 200 条搜索结果上限、原有独立历史窗口和主记录内存预算。
第六轮结束时 SessionController 从前轮约 972 行降至 891 行；第七轮继续拆导航和交互，见下节。

### 9. 导航意图与交互响应实例

第七轮提取 `session/navigator.ts`。NavigationHost 只提供导航状态、当前连接和所选会话修订号，
通过 leave/follow 回调交接所选会话；不访问 Transcript、模型目录或待答数据。
打开 picker、查找目标和创建会话接收前台取消信号。进入路径页、返回聊天、选择另一个会话或断线
使旧导航失效，迟到结果不能再次打开旧页面或切换会话。后台列表刷新不取得页面导航权，
列表请求序号防止较早读取覆盖较晚读取。停止等待任务收尾，失败时同时取消并行的剩余列表读取。
归档回执仍更新已完成的宿主事实，但只在原导航意图仍有效时打开列表；随后的刷新只更新数据。
创建已抵达宿主时，本机取消不能撤销创建，客户端只停止等待和选中该结果。

`session/interactions.ts` 保留待答请求并以具体请求对象持有一次响应。重复确认加入同一次发送；
进入会话写入队列后、真正发送前再次确认请求仍存在，宿主取消或替换的旧请求不再发送。
确认只删除自己对应的请求实例，同 ID 新请求不会被旧回执删除；失败释放响应所有权，允许显式重试。
响应继续复用 SessionMutationGate，保持与提示词、命令的同会话写入顺序。
用户的待答草稿仍由 SessionInfo 按所选会话管理。

`Client.listWorkspaces/listSessions` 接收 AbortSignal。取消工作区 baseline 会关闭订阅、移除监听器和计时器；
迟到帧不再更新归档集合，同步完成的 baseline 也能释放刚创建的订阅。
三个导航缺陷与三个交互缺陷在修复前已复现；另补响应重试、创建/归档迟到回执、订阅取消与同步完成回归。
SessionController 目前为 809 行；拆分依据是异步资源所有权，文件总行数不是优化指标。

### 10. 连接代际、握手与订阅资源

第八轮明确 Client 的寿命：对端断线不结束实例，允许保留 Cookie 重连；显式 close 永久结束实例，
后续 connect 不再打开 WebSocket。并发 close 共享同一次完成，握手失败/取消在物理连接清理后才拒绝，
旧 socket 的消息和关闭通知不能影响新连接。订阅发送同步失败也会撤销本地监听注册。

`controller/connection-streams.ts` 从重试循环中提取事件流、控制流与基线等待。
每个等待负责回收超时器和取消监听；同步建立失败、等待取消以及直接 close 都会结清资源。
ConnectionController 的代际信号贯穿认证后、握手后、基线后和应用初始化后的检查；
事件流失效立即取消其他基线等待并关闭 Client 的 HTTP 请求，保留原始失败原因。
停止不会继续进入下一阶段，也不再把迟到的认证失败显示为需要重新登录。
ConnectionStore 收窄为 online 与连接诊断发布，ConnectionStreams 只拿语义事件回调和诊断能力。

四项缺陷回归在修改前失败：关闭后重开、并发关闭过早返回、认证停止后继续握手、
事件流失效仍等待控制基线。补充实际握手取消、拒绝后重试、对端断线后重连，
以及基线计时器与订阅回收测试。认证策略保持原有约定：仅 HTTP 401 允许令牌回退；
新增 403、500、业务错误和网络错误四项测试，确认它们不会再次交换启动令牌。
本轮未修改 Cookie 存储格式或 token 策略；真实 SSH 与服务端重启仍属于最终环境验收。

### 11. 依赖语法检查与类型归属

第九轮将架构检查的正则扫描替换为 `tests/support/source-dependencies.ts`，使用已有 TypeScript 开发依赖。
三项新增缺陷回归在修改前失败：注释/字符串被误判为依赖、合法导入语法漏检、契约运行时代码漏检。
AST 读取静态 import/export、内联 type 标记、import type 表达式、字面量动态 import、require 与 import-equals。
含变量的动态路径显式报错；本地目标按源文件解析，缺失目标不会从图里静默消失。
契约以语法白名单检查，拒绝 let/var、enum、namespace、async function、值导入/导出及任意执行语句。
新增边分类、TSX、目标解析与强连通分量回归，保留原九条禁止方向（类型边同样受约束）。

初次 AST 扫描发现 106 个源码文件、495 条依赖、398 条本地边，无值依赖环；计入类型后有两组环。
它们不是已证实的运行时故障，而是类型放在了消费方或实现模块中：
`PromptRecord` 是 Transcript 的输出，移至 transcript.ts，SessionInfo 消费它；
`Command/LoopOptions` 被解析器和命令目录共同使用，移至 `slash/types.ts` 叶子。
原 info.ts/parse.ts 类型路径保留再导出，包外 API 不变。

调整后扫描 107 个源码文件、497 条依赖（145 条显式类型依赖）、400 条本地边（143 条显式类型边），
值依赖图与包含类型边的图均无环。架构回归分别检查两张图，防止共享类型再次形成反向依赖。
普通值导入即使只用于类型也按值边保守计入，所以这份图不是编译产物运行时行为的证明。
双语 README 与 tui-design.md 同步说明真实导入方向；移除“所有跨域都经过 index.ts”的不实描述，
并修正 session/catalog 可以导入根 State 的过时表格。内部具体模块导入不因此扩大公开包 exports。

### 12. 历史视图与窗口交接

第十轮提取 `ui/chat/use-history-view.ts`，集中管理阅读位置、折叠、实时推理展开、布局缓存、
历史保护以及翻页/跳转意图。hook 接收只读的记录元数据与明确操作回调，不导入应用 Controller 或领域模块。
卸载取消本视图发起的读取；更改滚动意图取消尚未完成的跳转，旧翻页结果不能覆盖新的阅读位置。
换会话重置显示状态，迟到结果同时检查记录身份、当前页面与取消信号。

临时历史窗口的交接移回 SessionController.openHistory：它选择已加载记录或获取独立页，
在安装前检查所选会话修订号，取消或失去归属时释放临时记录。UI 不再通过 queries.historyAt
取回可变窗口，也不再经 actions.setViewWindow 安装任意记录；替换为 openHistory(target, signal)
与 showLatest() 两个语义动作。普通公开 record/window 查询仍暴露内部记录，后续快照收窄尚未完成。
跨会话搜索逐步检查选择、快照和结果，失败或选中对象变化后不重新打开旧面板。
历史目标通过合并行索引定位，插入本地 shell 输出后仍落在对应宿主消息上。

卸载/滚动后仍安装迟到窗口的两项回归在修改前失败；修复后首轮聚焦回归 138/138 通过。
另补跨会话迟到搜索和插入本地块后的行定位回归。UI 入口目前为 987 行，
历史视图 hook 为 134 行；拆分旨在明确状态与取消归属，行数本身不作为性能证据。
卸载后的历史保护释放已在第十一轮核验；剩余公开可变读取面仍需迁移到显示快照。

### 13. 缺失产物、历史保护与遥测读取边界

第十一轮将 verify-first 与结算路径的小节检查统一到 `LoopExecution.artifactSection`。
工作区可见但文件或其子目录不存在时，按缺少小节处理，高分不能使该轮通过；
工作区不可见或读取失败时仍采用验证结论，并在没有既有说明时显示检查不可用的提示。
历史视图卸载时显式释放阅读保护，避免离开视图后继续阻止记录回收。

`queries.telemetry` 改为只有 ready/view/pending 的冻结读取门面，写入仍归会话域。
投影在接收时复制并递归冻结，队列复制并冻结条目；view 按会话缓存，接受更新时失效。
调用方保留的旧快照不会被新帧改写，也不能经读取结果修改内部状态。
这只收窄遥测读取边界：嵌套 JSON 的类型、公开 State、SessionInfo 和 Transcript 仍有后续工作。

### 14. 提示词回填收尾与范围约束

第十二轮将后台提示词回填移入 `session/prompt-backfill.ts`，绑定所选记录、选择修订号与客户端信号。
断线、换会话和释放记录均取消任务；停机等待已发出的回填结束，迟到结果不能发布或采用缓存。
等待初始快照使用连接的超时，分页维持原 200 页上限，每页合入后立即执行索引预算。
索引仅接收尚未保留的旧序号，前缀裁剪同步调整回忆游标；裁剪后撤销“已穷尽”标记，保持旧输入可回填。

用户提出过度改动的顾虑后，本轮限定为上述已复现缺陷及其生命周期验证。
公开 State、SessionInfo、Transcript 的可变引用是剩余设计风险，不单独构成全面迁移的理由；
后续先核对实际调用方与行为证据，不以增加接口、冻结对象或拆文件本身作为验收标准。
