# Agent Note: 阅读面板打开时输入历史仍然可达

Status: implemented

## Problem

任何面板打开都会禁用输入框的历史召回键，因为面板按键门禁把 `/status`、`/help`、`/cost` 和选择器一并算了进去。刚打开 `/status` 的读者无法按 `↑` 召回提示词，必须先关掉面板。为了让状态面板可以滚动而把方向键交给它，让这个问题更明显：即使面板一屏放得下、根本无可滚动，方向键也明显归面板所有。

## Decision

面板会报告自己的行数是否超过一屏可见范围，方向键、`PgUp`/`PgDn` 与滚轮只在超过时才归它所有。输入历史召回改用自己的门禁而不是面板门禁：状态面板只有在需要滚动时才出现在其中，因此放得下的面板把 `↑`/`↓` 原样留给历史，与面板出现之前一致。`Ctrl+P` 与 `Ctrl+N` 完全绕过该门禁，因此任何面板（包括需要滚动的那个）打开时历史仍然可达。`/help` 与 `/cost` 面板同样从不接管方向键，因为它们只用 `PgUp`/`PgDn` 翻页或根本不翻页。选择器以及问题、审批按键沿用原门禁，它们自己的方向键与数字键处理不变。

## Alternatives considered

在 `↑` 上关闭阅读面板被否决：读者要的是召回提示词，而不是关掉正在阅读的内容，何况之后可能还想继续看。始终把方向键交给面板被否决——那正是这次反馈的成因。从不把方向键交给面板也被否决：高于一屏的面板必须能滚动，而手机键盘没有 `PgUp`/`PgDn`。

## Consequences

`tests/ui/app.test.tsx` 在精简后的一屏能放下面板的终端上打开 `/status`，断言 `↑` 召回最近提交的内容、`Ctrl+P` 能到达更早的一条。`tests/ui/status-panel.test.tsx` 在 40×12、面板溢出的终端上打开同一面板，断言 `↓` 滚动面板且不触碰输入框，而 `Ctrl+P` 仍能召回。`tests/ui/key-routing.test.tsx` 把整张矩阵集中断言——无面板、放得下的状态面板、需要滚动的状态面板，以及 `/help` 与 `/cost`——因为这套按键路由已经坏过两次。
