# Agent Note: 重连后恢复终端待答交互

Status: implemented

## Problem

网关在事件流 ready 帧后立即重放未结束交互。终端此前会退回尚未选中对应会话的提问或审批，打开列表时也会释放等待请求。服务端可能随后以无人回答结束提问，使本可恢复的断线变成工具失败。

## Decision

在本次连接中按事件 ID 保留已识别的问题和审批帧，依据当前聊天会话生成可见待答列表，不依赖事件到达顺序。导航只隐藏其他会话的对话框，不回答或退回它。明确提交回答及服务端取消会移除条目；连接结束清空临时映射，以下次网关重放为准。不识别事件保持委托下一处理器的行为。

## Alternatives considered

本地持久化事件 ID 和弹窗，无法在取消、工具失败或服务端重启后复活服务端 Promise。从历史工具文本重建待答问题，会使已结束调用看起来仍可回答。只延迟启动阶段事件，无法解决切换列表导致的失败。

## Consequences

恢复要求原服务端和提问仍存活。正常退出 TUI 仍取消运行中的轮次，客户端崩溃不保留未提交的部分回答。失败的 ask_user_question 需要新请求，不能重放旧答案。隔离网关夹具在选择会话前及重连后重发事件；测试同时验证导航不发送 next、明确回答后移除对话框。类型检查、构建和终端测试通过。
