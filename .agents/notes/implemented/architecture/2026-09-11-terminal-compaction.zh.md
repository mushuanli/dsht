# Agent Note: 终端压缩命令与窄屏思考折叠

Status: implemented

## Problem

终端用户需要手动压缩上下文，且命令文本不能作为提示词排队。流式思考在完成并折叠之前，可能占据窄屏的大部分空间。

## Decision

`/compact` 调用 `commands/execute`，传入所选 `agentId`、完整命令及空 `submittedAttachments`。服务端负责空闲检查和压缩。终端显示进度及返回文本；命令不存在、返回值格式错误或执行失败时保留草稿。压缩可能需要较长的模型调用，因此请求不使用普通 RPC 超时，但调用方取消与客户端关闭仍会中止请求。客户端不会自动重试修改操作；响应丢失时无法确定服务端结果。

内容区域少于 60 列（终端少于 62 列）时，单行模式下的思考在流式接收期间也会折叠。显式 `/think live` 展开覆盖该默认值，直到再次切换或助手尝试发生变化。宽屏继续在流式接收时展开、完成后折叠。宽度已包含在历史行缓存标识中，因此调整窗口会重新计算显示，不会修改保留的思考文本。

## Alternatives considered

把 `/compact` 当作提示词发送，会将其排入模型输入队列，而非调用面向用户的命令。普通 15 秒超时可能丢失耗时较长的成功命令响应。所有宽度都展开实时思考，会在手机终端上挤占正文与输入区域。

## Consequences

终端需要服务端提供命令插件，缺失时会提示。命令结果属于本地反馈；终端历史尚未渲染持久化命令生命周期卡片。HTTP fixture 测试覆盖结果、取消和超时覆盖；历史与界面测试覆盖宽度变化及手动展开。移动端 SSH 显示仍需设备验证。
