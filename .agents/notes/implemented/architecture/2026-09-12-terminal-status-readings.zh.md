# Agent Note: 状态栏为两组数字各带一种更完整的读法

Status: implemented

## Problem

去掉上下文条状后，占用比例反而比它替代的条状更难读；两个费用列（`S¥2.49*`、`D¥113.25*`）把字符花在范围字母上，而状态栏从不显示账号累计花了多少。界面也无法同时表达这两件事，因为同一个字段列表同时决定显示顺序与丢弃顺序：分组被丢弃的位置就是它显示的位置，于是费用的更完整读法除了占用本会话列的位置之外无处可放。

## Decision

两个分组各带同一数值的第二种读法。上下文占用画成 `ctx: ███░░░░░░░ ~30%`，十格表示十分之一，与纯文本 `ctx 30%` 并列。费用画成 `¥: 3.00 (13.00)`，即今天花费加括号内的历史总计——`CostLedger.total()` 在不限定会话与天数时会把每一笔计费相加——与保持本会话口径的纯文本 `S¥3.00*` 并列。

更完整的读法只会在整行仍放得下时替换它所属的分组，因此两种读法都不会挤掉本已放得下的分组：109 列时最宽的一行同时容纳条状与双口径费用，各自在自己的宽度以下退回纯文本，而不是去挤掉模型或回合数。只剩费用一个分组的那一行就是紧凑布局，它保持本会话口径，于是宽状态栏显示今天花费与历史总计，窄状态栏仍然回答它正在驱动的那个会话。状态栏只有一个费用槽，账本有本会话切片时用它，没有时用今天花费，因此没有缓存切片的会话仍会报出费用。

显示顺序现在与丢弃顺序相互独立。一行依次读作状态簇、模型、档位、上下文占用、费用、回合与 token；而放弃宽度的顺序是费用、占用、模型、档位、回合、token。费用因此排在它旁边被一起读的占用之后，并且仍然是最晚被丢弃的分组，宽度不足时移到第二行而不是消失。

## Alternatives considered

允许更完整的读法挤掉放得下的分组被否决，因为状态栏会用一个已经在行上的数字的更宽画法换掉模型或回合数。按宽度阈值选择费用口径被否决，因为阈值将不得不跟随模型名、token 总量与终端字体变化。把范围字母保留为独立列被否决，因为今天花费与历史总计这两个数合起来提供的信息多于两个“本会话／今天”标签，而且在双口径替换一列之后不再多占一个分组。把条状格数缩短以提高出现频率被否决，因为十格可以一眼读出，五格分不清三分之一与一半。

## Consequences

`tests/ui/status.test.ts` 固定两种读法各自的宽度，断言显示纯文本时该行仍含 token 总量，并断言紧凑布局保持本会话口径。`tests/expected/status-compact.txt` 记录最宽的一行，`tests/ui/app.test.tsx` 覆盖没有缓存切片的会话。历史总计只是账本记忆化合计里多出的一个键，因此多出的这次读法每次渲染只多一次缓存查询，而不是多一次扫描。
