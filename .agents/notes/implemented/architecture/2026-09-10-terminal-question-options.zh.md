# Agent Note: 用户问题的键盘选项选择

Status: implemented

## Problem

终端此前只把问题选项拼成一行文本，所有回答均作为自定义文本提交，没有网页问题输入器的选项选择和多选行为。

## Decision

显示题目进度、标题、编号选项、说明和多选框。方向键移动高亮项，数字 1–9 定位单选项或切换多选项，Enter 明确确认。空格切换当前高亮多选项。Other 条目将输入交回输入框，支持纯数字自定义文本。快捷键只在输入框为空时生效，复制模式和其他面板中不执行。

回答状态按交互及题目位置区分。选中标签沿用 `{ id, selected, custom? }` 协议，最后一题完成后一次提交全部答案。多选回答可同时包含选中标签和自定义文本。提交失败时保留当前选择及草稿。键盘确认不会从推荐文案推断批准。Esc 和 Ctrl+C 保留待答交互，`/cancel` 仍为明确取消入口。

待答问题和审批替换历史可见区域，容器及选项行不参与压缩，避免切换到更高的后续问题时，与冻结历史争夺高度并使标题、标签被压为零行。选项窗口按终端高度计算并跟随高亮行。回归测试回放长会话，从短的第一题进入包含说明的第二题，再缩小终端，检查选中标签和确认提示。

## Alternatives considered

数字键立即提交会使误选难以纠正。将选项编号编码成自由文本会丢失服务端结构化选项标签。打字时捕获数字键会阻止数字回答。从历史文本恢复选项状态会混淆已完成和仍待答的交互。

## Consequences

前九个选项支持数字快捷键，更长列表使用方向键和有限的可见选项窗口。部分回答在最终提交前保留于本地，不跨进程持久化。测试验证单选、多选、说明、纯数字自定义回答、确切结构化报文和提交失败重试。类型检查、构建及专项终端测试通过。
