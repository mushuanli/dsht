# Agent Note: 历史行改以兄弟文本节点渲染

Status: implemented

## Problem

Ink 把文本节点的度量结果缓存在 `measure-text.js` 与 `wrap-text.js` 的模块级缓存里，且从不淘汰。在运行中的客户端上给这两个缓存插桩后可见：换行缓存始终为零条，而度量缓存每帧新增一条，因为视口把全部可见行放进同一个文本节点，被度量的键因此是整屏文本。实时尾部一变化该键就重新生成，于是长时间会话会按帧数保留整屏字符串：两百个流式增量占用 148 KB，约每帧 735 字节，并在进程存活期间一直保留。重启进程会丢弃这些内容，这正是重启后内存下降、而对话记录、账本与布局计数器始终停留在兆字节量级的原因。

## Decision

`HistoryViewport` 改为渲染一列兄弟文本节点，每个已换行的行一个节点，而不再用一个文本节点容纳所有行。被度量的键变成单个变化的行，未变化的行因此命中缓存，只有增长中的实时行新增条目——条目数相同，但约每帧 50 字节，保留的键字节数减少到十五分之一。样式片段仍作为该行内部的嵌套文本节点渲染。空行渲染为一个空格，因为 Ink 不会给空文本节点任何高度；探针确认其帧输出与原来的嵌套渲染逐字节相同，既有的 golden 与终端测试也全部原样通过。

## Alternatives considered

保留单文本节点并给 Ink 的缓存加上界被否决，因为这些缓存是模块私有的，我们能控制的上界只有交给单个节点的文本量。预先切分实时尾部被否决，因为那会改变换行，从而改变可见输出。升级 Ink 被否决，因为核查 7.1.1 后确认其缓存同样没有上界，因此要修的是这里的单节点文本量，缺失的淘汰属于上游。

## Consequences

残余增长为每个流式帧一条很小的缓存条目，因此上界取决于帧数，而不再取决于帧数乘以视口大小。节点数上升到可见行数，由 Ink 按行协调；内存探针、完整测试套件与 `test:terminal` 都已针对该改动重跑。依据写进 `src/ui/chat/history-view.tsx`，因为空行的空格与兄弟行布局只有合在一起才有意义。
