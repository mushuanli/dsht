# Agent Note: 带索引的终端历史与思考导航

Status: implemented

## Problem

长会话同时保留原始工具正文、已完成的流式分片，以及完整和折叠后的重复展示字符串。每个流式帧重新拼接全部历史终端行，使展示成本随历史长度增长。全局思考开关也无法让用户按 prompt 定位某段思考。

## Decision

服务端持有持久日志。客户端保留语义消息块和未结束的旧版分片，释放不用展示的工具结果正文及已结束分片，并独立保存分页位置和当前轮次标记。完整文本按需拼接，折叠状态与内容分开。prompt 和思考摘要使用按序号缓存的索引，流式增量不使其失效；读取更早页面后会更新与前一条已加载用户 prompt 的关联。

历史保留消息行数、位置索引、最多 2,048 行的 LRU 及可见区域读取接口。流式更新复用已提交历史的索引。思考块结束或正文／工具开始输出时，当前思考自动折叠。`/think` 列出已加载摘要和当前尝试，按用户操作读取更早页面，并在原位置展开选中的消息。列表使用方向键和 Enter，尚未实现鼠标点击选择。

标题和输入框固定在按实际高度计算的对话区域两侧。为终端保留一行，避免进入 Ink 的全高擦除重绘路径。通用快捷键说明放在 `/help`。Catppuccin Mocha 是独立的语义主题，远程文本清理后才附加 ANSI 样式。工具调用保留描述和缩进两格的命令第一行，不把嵌套工具结果复制进展示存储。

工具结果按调用 ID 更新原调用的状态，保留描述及缩进命令，不再重复增加结果行。调用页尚未加载时保留独立结果摘要，加载后合并。投影缓存键包含相关调用状态，使无关消息继续复用缓存块；普通流式帧复用完整投影。

## Alternatives considered

**本地 SQLite 或文件归档。** 将正文放到磁盘可以限制内存并支持离线历史，但需要异步正文加载、快照替换时的缓存失效及独立的数据生命周期，也无法消除全历史排版成本。当前客户端沿用服务端分页接口，并优化已测得的展示瓶颈。

**保留全部排版行。** 这样便于按行查找，却会长期保存与终端宽度相关的会话副本。有限行缓存以偶尔重新排版换取较少的展示内存。

**展开全部思考。** 它改变整个对话高度，也没有按用户 prompt 定位的入口。列表展开单条思考，并保持其他消息的折叠状态。

## Consequences

实时 transcript 默认以 2,000 条记录或 16 MiB 估算量为可配置软限制，回收目标为 75%，并保护最小近期尾部。淘汰时保留分页游标、前置 prompt 摘要及工具调用名称。切换会话释放旧正文和排版。回看时保护历史窗口；`/latest` 释放独立搜索窗口并恢复实时尾部回收。离线历史和未结束流保持受保护。`/search` 独立扫描每页最多 80 条消息，释放临时 transcript，只保留最多 200 条不引用原始正文的短摘要。目标跳转加载独立页面，主 transcript 继续接收实时输出。稀有词或无匹配查询仍需完整 HTTP 扫描，服务端索引留待后续实现。首次排版、调整终端宽度和展开特别大的单个内容块仍需处理对应全文，没有客户端总内存硬上限或离线磁盘归档。思考列表首次只索引已加载历史，而非所有服务端记录。原始工具结果正文只保留在服务端日志中。

无密钥终端测试还验证预算回收、重载游标、会话释放、有界搜索及返回实时输出，并覆盖可见区域缓存淘汰、旧版分片释放和更早页面回放、思考选择与按需翻页、命令预览、角色颜色和固定标题滚动。`npm run typecheck`、`npm run build`、`npm run test:terminal` 均通过。`npm run bench:history` 测量本地排版及 25 行可见区域，不含网络或模型工作。在相同的一万条消息合成输入下，每帧中位耗时由 2.224 ms 变为 0.334 ms，P95 由 14.083 ms 变为 0.590 ms；进程堆读数并非受控的内存基准。
