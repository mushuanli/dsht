# Agent Note: 状态栏按价值保留分组

Status: implemented

## Problem

单行状态栏描述的是"列"，而不是"答案"。在 46 列下它把十五个字符花在 `Ctrl+C Stop` 上，把上下文百分比紧挨着金额显示，于是 `~¥2.49/~¥113.25* ███░ ~30%` 读起来像"预算及其用量"；而费用——状态栏存在的少数几个数字之一——却在上下文占比和模型名之前就被丢掉。`Working` 被完整写出来，尽管图标和运行计时已经表达了它。暂停的时钟只是冻住，不说原因；而时钟在三种情况下都会冻结（copy mode、对话框打开、回看历史），所以一个停住的数字与卡死无法区分。

## Decision

分组按价值装填。保留顺序是：状态簇（运行时 `◐ 6:18`、`● Ready`、`⏸ <原因>`、`! Offline`、`⚠ Error`）、当前阶段、停止提示 `^C`、费用、上下文占比、模型、effort、回合数、token 总量。宽度不足时先丢价值最低的分组；费用永不丢弃，只会挪到第二行；状态簇只在约二十列以下才让出阶段与停止提示。费用与占比后来各带同一数值的第二种读法，显示顺序也与保留顺序分离（[读法](2026-09-12-terminal-status-readings.zh.md)）。

阶段是事实而非推断：`Transcript` 记录阶段开始时刻，因此推理的增量显示为 `think 28s`，工具显示为 `<名称> 1:08`，流式回答正文显示为 `write 12s`。不从静默推断任何东西，因为长时间推理与安静运行的工具都属正常，而且协议里根本没有卡死信号。`app.tsx` 传入暂停原因（`copy`、`dialog`、`history`），让冻结的时钟自报原因；状态栏还会上报自己的行数，因此它占两行时 `/status` 面板的每页预算会相应减少。

## Alternatives considered

只调整丢弃顺序、保留列布局被否决：活动列的补白正好是窄终端最缺的宽度。从一段静默推断卡死此前已被否决，这里再次否决：它会对长推理误报，而且宿主并不发布按回合的存活信号。按已运行时长给工具着色被否决：客户端看不到工具的 `timeoutMs`，而各工具的正常耗时相差数量级。完全去掉今日合计被否决——一旦用作用域字母（`S`/`D`）消除了歧义，它就不再需要被丢弃。

## Consequences

`tests/ui/status.test.ts` 在十一个宽度上断言装填阶梯、宽字符模型名不溢出、远端文本无法夹带控制字符或换行，以及计时与阶段的确切格式。`tests/ui/app.test.tsx` 断言放得下的面板、各暂停原因，以及重连后状态栏会丢掉它已无法支撑的分组。新增的只有阶段开始时间戳，它在阶段切换时写入而非每帧写入，因此状态栏对每个增量零开销。
