# Agent Note: 终端工作区移除与会话归档

Status: implemented

## Problem

工作区和会话选择器只能打开条目，没有网页导航中的移除入口。归档状态也需要在刷新选择器后继续生效，避免会话重新出现在全部会话列表。

## Decision

在真实列表条目上、输入框为空时按 `d` 或 Delete，打开包含确切名称、ID 及适用工作区路径的确认页。导航命令接受 `--delete`，会话导航另支持 `--archive`。确认前沿用无歧义目标解析，提交时使用已确认的 ID。默认选中取消，Esc 关闭确认页，其他命令关闭旧确认页。辅助导航条目没有移除操作。输入框仅在导航选择器且草稿为空时保留 `d` 快捷键；已有草稿保持普通输入。打开确认前区分原始 Delete 序列和 Backspace。

只调用服务端现有 API：`workspace/delete` 移除工作区注册，不删除目录或会话；`workspace/archiveSession` 隐藏会话，不删除日志或停止任务。确认页说明这些影响。工作区基线中的 `archivedSessionIds` 用于过滤工作区内和全部会话列表；仍可按确切 ID 重开已归档历史。

成功归档当前会话时释放 transcript 和终端行缓存。移除当前工作区时清除工作区关联，保留已打开会话。API 拒绝时保留确认页和可见条目。变更成功后刷新列表失败，明确报告移除已完成。

会话移除先刷新服务端列表，再决定是否需要确认。明确为空且空闲、没有已知排队任务或本地提示词提交的会话直接归档。当前加载的 transcript 大小和标题不作为空会话依据。过期列表中的会话如果已经不为空，仍打开确认页。API 没有原子性的空会话删除操作；归档保留日志，不中断并发启动的任务。

## Alternatives considered

删除服务端文件会绕过受支持 API，并可能破坏会话历史。将归档表述为永久删除会误报操作能力。收到确认前乐观移除会在请求被拒绝后隐藏条目。按键直接删除会跳过对象和影响范围核对。

## Consequences

当前公开 API 只提供归档，因此没有永久删除会话命令。运行中的任务继续，工作区文件保持不变。回归测试使用隔离 HTTP 夹具验证取消、确切报文、拒绝和重试、刷新后的归档过滤、重开历史及当前 transcript 释放。类型检查、构建及终端测试通过。
