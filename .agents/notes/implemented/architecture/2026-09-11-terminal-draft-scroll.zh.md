# Agent Note: 新草稿把视口带回实时末端

Status: implemented

## Problem

在长对话里往回读之后，视口会停在滚动到的位置。此时要写消息，就得在发送前重新找到实时末端：每几行一次滚轮或 `PgUp`，或者用 `/latest` 命令。草稿的开始与视口位置之间没有任何关联。

## Decision

当草稿由空变为非空、当前界面是对话、且首字符不是 `/` 时，`setInput` 把视口带回实时末端。判断依据是"从空草稿变成非空"这一转换，而不是"草稿非空"：已经有草稿的读者向上滚动时会保留自己的位置，因此在历史里核对内容不会和输入框互相打架。斜杠命令不是消息，所以输入它以视口不动为前提——`/search` 与 `/think` 本就是用来在历史中移动的，把它们打出来的过程中把读者拽到底部等于撤销这个动作。

## Alternatives considered

只要草稿非空就回到实时末端被否决：这样后续每敲一个键都会把有意滚上去、手里还握着草稿的读者拽回来。像 `/latest` 那样连已加载的历史窗口一并丢弃也被否决：敲一个字符不该丢掉读者打开过的搜索结果或更早的页面；而发送时本来就会清掉该窗口。在输入框旁加提示被否决：这个行为不需要说明，它只会减少一次滚动。

## Consequences

`tests/ui/app.test.tsx` 把一段四十条记录的对话滚离实时末端，断言输入 `/` 后视口原地不动、开始写消息会带草稿回到实时末端、以及握着草稿滚走后继续输入仍保留读者位置。推导视口位置的 `useLayoutEffect` 与历史 pin 逻辑本就会对滚动值作出反应，因此没有引入新的状态。
