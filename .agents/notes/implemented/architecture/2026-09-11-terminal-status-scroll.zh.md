# Agent Note: 状态面板改为滚动而不是翻页

Status: implemented

## Problem

展开的 `/status` 面板按 `PgUp`/`PgDn` 在固定页之间跳转，而手机键盘有方向键却没有翻页键，因此在手持设备上第一页之后的内容根本够不到。翻页还会在任意位置切开面板：一个跨过页边界换行的值会一半留在上一页底部、一半出现在下一页顶部；页脚也只报页数而不报屏幕上到底有多少行，读者无法判断自己读到了哪里。

## Decision

面板现在持有的是行偏移而不是页号。`↑`/`↓` 移动一行，`PgUp`/`PgDn` 移动一屏，面板打开时滚轮滚动面板而不是背后的对话。页脚报出可见行区间与总行数，并提示方向键，因此没有翻页键的终端也知道如何移动。滚动越过两端时会停在最近的一屏，并通过 `onScroll` 把最终偏移回报给应用，使应用状态与显示保持一致，而不是让一个看不见的越界偏移不断累积。

面板现在是独立组件。它是唯一需要滚动的分支，并且需要一个副作用来收敛偏移；若留在被 memo 的栏组件里，这个 hook 就会落在折叠分支提前返回之后，从而在两个状态之间改变 hook 顺序。

## Alternatives considered

保留翻页并额外支持方向键被否决：页边界依然会切开换行的值，读者也依然看不出翻一页到底覆盖了多远。让面板溢出屏幕被更早地否决过，因为超出高度的行会被丢弃而不是显示。把 `/status` 改成 `/help` 那样的全屏对话框被否决：那比这份报告所需的改动更大，面板有意与输入框共享屏幕，以便边写边看。

## Consequences

`tests/ui/status-panel.test.tsx` 逐行走遍一个可滚动的面板，断言没有任何明细行被丢掉、没有任何值出现省略号、页脚报出可见区间，以及越过末尾的滚动会停在最后一屏并回报该位置。它还在 40×12 的终端上通过运行中的应用驱动 `↓`、`↑`、`PgUp`、`PgDn` 与 Esc。另有独立的应用测试固定手机粘贴的行为：整段片段作为一次输入投递，换行与制表符折叠为空格，且不会发出提示，因此粘贴多行文本不会误发送。
