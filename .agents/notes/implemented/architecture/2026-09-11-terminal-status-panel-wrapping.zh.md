# Agent Note: 窄屏状态面板换行并分页

Status: implemented

## Problem

展开的 `/status` 面板用 `truncate-end` 绘制主机与工作区两行，于是在窄终端上，较长的 URL、宿主状态或工作区路径会丢掉尾部。该面板还与两行表头和三行输入框共享屏幕，而这两部分不会收缩，因此当面板高于剩余空间时会被裁掉：24 行的终端上，几个较长的值就足以丢行；更矮的终端则同时丢掉面板顶部和底部边框。

## Decision

每条明细都是一个纯文本行，在交给 Ink 之前就按面板内容宽度硬换行，因此没有任何值被截断，也不需要 Ink 再折一次。应用传入的每页行数为 `rows - 9`：面板自身占两行边框与一行页脚，而它上方的两行表头和三行输入框不会收缩。页脚高度会单独再测一次，因为分页提示本身在窄终端上也会折行，它占用的行装不下明细。`PgUp`/`PgDn` 翻页，打开面板与 Esc 都回到第一页，冻结标识包含页码，因此画面暂停时翻页仍会重绘。

## Alternatives considered

保留 `truncate-end` 并接受信息丢失被否决：完整信息正是这个面板存在的意义。只让 Ink 换行而不分页被否决：超出屏幕高度的行会被裁掉而不是显示出来。用 `more` 计数标记截断处同样被否决。为精确得出预算去测量输入框被推迟：这里的常量与 `/help` 现有的分页方式一致。

## Consequences

`tests/ui/status-panel.test.tsx` 在 44、32、24 列下渲染面板，断言不出现省略号且工作区路径与宿主状态完整保留；它遍历每一页，断言没有任何明细被丢掉、页脚标明页码、越界页码停留在最后一页；并在 40×12 的终端上通过运行中的应用驱动 `PgUp`、`PgDn` 与 Esc。`tests/support/tty.ts` 让组件挂载到指定尺寸的终端上，因为 `ink-testing-library` 把输出固定为 100 列且没有高度。
