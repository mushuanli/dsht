# Agent Note: 索引终端历史中的 Markdown

Status: implemented

## Problem

对话行直接折行 Markdown 源码，表格无法按列对齐，Mermaid 和 TeX 也只能显示难以阅读的源码。如果只在 React 可见区域渲染富文本，历史索引测量的位置会与实际显示行数不一致。

## Decision

会话排版使用 Marked 解析正文，再索引终端行。标题、行内强调、链接、列表、引用、代码块和 GFM 表格生成纯文本行及本地样式片段。Ink 在排版后应用样式；远程控制符在解析前及实体解码后移除。思考和工具部分保留原有展示方式，transcript 保留用于搜索及服务端日志导出的源码。

表格按终端列宽分配空间，在单元格内换行。平均每列无法保留十二个内容列时，改为带标签的纵向记录。Beautiful Mermaid 将支持且闭合的图表渲染为 Unicode 网格。依赖按代码单元测量，因此中文宽字符额外预留网格空间。未完成、不支持或过宽的图表显示源码，避免破坏网格。

MathJax 编译基础和 AMS TeX，不自动加载扩展，也不共享宏状态。终端 Unicode 公式保留分式、根式、上下标和矩阵的分组；终端不支持的 MathML 节点保留 TeX。HTML 导出使用 MathJax 生成的 MathML 和 Mermaid SVG 图片文档，原始 HTML 转义，不执行脚本或加载远程资源。导出只包含保留的对话和实时尾部，工具行仍为摘要。排他写入保护已有文件，取消时移除未完成输出。

出现 Markdown 语法前，纯文本继续增量折行。富文本实时正文重新解析，因为后续表格分隔行、引用定义和闭合围栏可能改变前面的行。不可变内容块缓存避免在未变化的帧上重复处理。图表和公式文本缓存最多保留 128 项，源码与结果字符总量不超过 256 KiB；超过 16 KiB 的公式和图表保留源码。实时内容块消失时，移除对应的排版状态。

## Alternatives considered

**只在可见区域使用 Markdown 组件。** 历史索引完成测量后再改变行高，会破坏滚动位置和分页。

**只用浏览器渲染。** 这会使 SSH 中的表格和普通格式仍然难以阅读。终端直接渲染支持的内容，离线 HTML 提供完整数学排版。

**流式输出时冻结较早的富文本行。** Markdown 可以在后续分隔符到达后重新解释前面的内容。纯文本保留增量折行，富文本块重新解析以保证正确。

## Consequences

富文本流式处理的成本随当前正文长度增长，与纯文本快速路径不同。Mermaid 支持依赖提供的图表类别，而非全部 Mermaid 语法；公式在终端中近似呈现数学排版。浏览器导出是保留历史的视图，不替代日志归档。32 列和 100 列的无密钥对话快照覆盖中文表格、样式、代码、图表及公式。分片回放比较流式输出与完整解析，界面测试覆盖 ANSI 行宽和本地 HTML 导出命令。
