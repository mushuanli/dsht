# Agent Note: 终端审批编号选项

Status: implemented

## Problem

审批此前只能通过输入 `/allow` 或 `/deny` 回答，而其他待答交互都已提供可见、可选择的列表。用户决定是否放行某个工具调用时只能看到请求正文和一行提示，决策依赖记住两条命令，且输错命令与有意拒绝很难区分。

## Decision

审批请求渲染三个编号选项：`1. Allow once`、`2. Deny`、`3. Stop turn`。选项 1 和 2 对应服务端的 `allowed-once` 与 `rejected` 结果；选项 3 通过 `session/cancel` 取消当前轮次且不发送事件结果，行为与 `/cancel` 完全一致。`/allow`、`/deny` 和 `/cancel` 命令仍然可用。

输入框为空时，用数字 1–3 或方向键选择，只有已经选中某项时 Enter 才会确认。列表初始不选中任何项，因此误按 Enter 不会回答请求；从未选中状态按方向键会落在第一项，而不会落在 `Stop turn`。Esc 清除高亮且不回答问题。选择以交互身份为键，并在请求消失或连接世代变化时清除，因此重连后被重放的请求会重新回到未选中状态。

只有在审批占用键盘时，输入框才保留数字 1–3。非空草稿保持正常输入，测试通过 `/allow` 加 `2` 组成 `/allow2` 固定这一点；普通提示词路径仍然可达。

审批选择器、提问选择器与输入回填共用的对话框排除条件已合并为一个谓词，新增面板不会悄悄让审批按键继续生效。

## Alternatives considered

默认选中 `Allow once` 会让一次 Enter 就放行工具调用，而这正是确认环节要避免的结果。从未选中状态按向上键落在列表底部会把 `Stop turn` 首先高亮，可能因误按而取消正在运行的轮次。按下数字即提交会去掉提问选择器同样保留的确认步骤。

从请求载荷读取可选结果被否决，因为服务端并不公布该集合；两个结果加取消动作由 wire 协议固定。把标签接入本地化文案未采用，因为该终端所有界面字符串均为英文，只有 README 是双语的。

## Consequences

提问、选择器和输入回填的键盘约定不变，只有审批新增了选择器。`npm run typecheck` 与 `npm test`（133 项）通过，其中一条用例固定未选中起始、Esc 重置、重放重置以及确认前不产生事件结果，黄金文件 `tests/expected/approval-options.txt` 固定渲染出的列表。

README 配对文档记录了该选择器，`README.i18n.yaml` 记录了评审后的哈希。三个标签与界面其余部分一样保持硬编码英文；本地化字典随界面整体翻译一并推迟。
