# Agent Note: 输入框保真粘贴内容，且不再吞掉对话区

Status: implemented

## Problem

输入框只有一条逻辑行。插入时 `[\r\n\t]+` 被替换成一个空格，因此粘贴的日志在发送之前就被改写：手机端最核心的用法——贴一段失败日志、问根因——交给模型的已经不是用户贴进来的字符串，换行与缩进全部丢失。同一个输入框也没有高度上限。在 44×16 下实测：120 字符的草稿已占 6 行，500 字符的草稿占满 15 行中的 13 行——对话区被压到 0 行、底边框离开画面、状态栏消失。两个缺陷互相放大，因为被拍平的内容正是折行最严重的那条长逻辑行。既有测试把拍平行为固定为预期，所以没有任何信号暴露它。

## Decision

保留字节，约束显示。插入时把 `CRLF`/`CR` 归一为 `LF`，保留制表符，只剥离其余控制字符。wire 不变：`session/prompt` 本来就是 `content: [{ type: 'text', text }]`，而 transcript 已经通过 `wrap-ansi` 正确渲染换行，因此多行草稿既能显示也能原样发送。

新增纯函数模块 `src/ui/input/viewport.ts`，在每次渲染时从文本推导布局：按字素折行并支持硬断行、制表符按四列制表位展开、光标所在行与列、跟随光标的行窗口，以及折叠块占用的源码区间。这里不保存任何状态，所以剪除、历史回填、草稿寄存还原等任何编辑都不需要重定位区间。

`app.tsx` 只按终端行数分配窗口：`body = 总行数 - 根框 - 页眉 - 状态栏 - 一行瞬时提示`，内容行取 `clamp(floor(body / 3), 2, 5)`，再受 `body - 7` 约束，从而始终给对话区留出至少四行。列数不参与高度计算，所以横屏与宽终端只会减少折行。未折叠视觉行数超过窗口的多行草稿会把中间行折叠为 `[N lines · X KB]`，首行与末行保持可见；判定读取未折叠高度，因此折叠不会反过来触发自身并产生震荡。

对 `editInput` 而言，一个折叠区间就是一个对象：`←`/`→` 一次跨越，区间尾端的 Backspace 与首端的 Delete 删除整块，按词或按字符的移动会跳出区间而不是停在内部。显式剪除（`Ctrl+K`、`Ctrl+U`）仍按字符工作，折叠随后重新推导。按键没有变化：Enter 仍是提交，Esc 保持既有取消语义，`↑`/`↓` 仍归历史回填。

布局每次按键都会重算，因此必须保持廉价。当逻辑行数本身已超过窗口时，中间内容完全不参与折行——只排版首行与末行——394 KB / 5000 行的草稿从每次约 66 ms 降到 0.14 ms。

## Alternatives considered

"输入到第五行自动打开全屏编辑器"被否决。换行仍被拍平时这个触发条件根本不可达；Esc 在本客户端已是既定的取消手势；打字中途整屏换布局还会遮住用户正在读的对话。

一期用启发式识别粘贴被否决。没有 bracketed paste 时无法区分粘贴与快速输入，而 Ink 6 不解析 `ESC[200~`/`ESC[201~`——它把标记当普通文本投递——所以猜错的代价高于用中性标签。保存 paste span 同样被否决，原因有二：从文本推导的折叠无需重定位，而保存的区间必须在历史回填、草稿寄存还原与每次编辑后重建。

以字节数为阈值（40 B，或退一步的 512 B）被否决：字节不等于屏幕占用，40 B 已经是一个普通英文句子，十几个汉字就会超过。第一判据是视觉占用，超长的单行 prompt 应该滚动，而不是变成对象。

把制表符换成空格被否决，因为那会破坏 Makefile 一类内容。制表符保留在草稿里，只在显示时展开，因此 viewport 的宽度计算与终端一致，而发送内容不变。

把 `↑`/`↓` 改成草稿内按行移动在一期被否决：方向键归属矩阵由 `tests/ui/key-routing.test.tsx` 固定，而折叠块只用 `←`/`→` 就能完整导航。

## Consequences

`tests/ui/input-viewport.test.ts` 固定折行、制表位、光标定位、窗口与折叠判定，包括"超长单行永不折叠""判定不会震荡"，并同时覆盖两条排版路径——逻辑行数本身超过窗口，以及只有折行后才超过窗口——以免二者走偏。`tests/ui/input.test.ts` 固定行尾归一、制表符保留、控制字符剥离与折叠块手势。`tests/ui/app.test.tsx` 用两个测试取代原先的"粘贴变一行"：换行与制表符被显示并原样发送；高块被折叠而 Enter 仍发送完整原文。`tests/ui/composer-layout.test.tsx` 在 44×16 与 80×12 下挂载，断言 500 字符草稿之后对话区、底边框与状态栏都在，并断言窗口跟随 body 行数而不是列数。

bracketed paste、`View paste`/`Edit paste` 面板、逐行光标移动，以及 `@` 引用菜单与对话框的高度预算仍属后续工作；composer 自身已经有上限。
