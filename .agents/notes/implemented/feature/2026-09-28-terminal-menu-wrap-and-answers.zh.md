# Agent Note: 菜单方向键循环、数字直接作答、无文本框的面板停用输入框

Status: implemented

## Problem

三处键盘缺陷让菜单用起来像是坏了，尽管每个按键本身都有文档。

- **没有菜单循环。** `Picker`、`/loop` 记录列表、`@` 补全列表、提问选项环、审批列表与循环参数表单都在边界处截断（`Math.max(0, …)` / `Math.min(length - 1, …)`），方向键因此在首行与末行变成死键，读者只能反向走完整份列表。
- **数字只移动高亮。** 审批与单选题都写着 `1–3` / `1–9`，但按数字只是移动高亮，仍然要再按一次回车。设计早已把数字当作显式作答，于是实现与文档互相矛盾。
- **无文本框的菜单让输入框继续活着。** 面板类菜单（`/model`、`/prompts`、`/queue`、`/history`、`/think`、删除确认）接管了方向键却不接管文本：敲给列表的键会变成草稿，而每个选择器在草稿非空时会把自己禁用（`enabled={!input}`、`canSelect={() => !input && …}`），于是这份草稿悄悄杀死了它被敲向的那个菜单。

## Decision

- `src/ui/dialogs/picker.tsx` 的 `cycle(index, delta, length)` 是唯一的循环规则，`Picker`、`/loop` 记录列表、`@` 列表、提问选项环（比选项多一站，因为 `Other answer` 也是一行）、审批环与循环参数表单共用它。首行按 `↑` 落到末行，末行按 `↓` 回到首行，空环停在 0。
- **数字就是作答，而不是高亮。** 审批的 `1`/`2`/`3` 立即提交 `allowed-once` / `rejected` 或取消当前轮次；高亮仍会先设置，因此失败时留下可见的选中项。单选题的数字直接结算该题，整组问题因此不必多按一次键就能推进。多选题的数字仍是勾选／取消勾选，因为一个标签不等于全部答案。只有固定选项带编号：`Other answer` 是输入行，所以不编号，用方向键加回车到达。
- `usePanels` 为不读自由文本的面板新增 `parksComposer` 标记。`ui/app.tsx` 由它派生 `panelParksComposer`，在这类面板打开期间关闭输入框的 `focus`，与审批／提问对话框原本寄存草稿的方式一致。`/help`、`/cost`、`/status` 保留输入框——按键路由测试依赖它们回填历史——启动时的工作区／会话选择器也保留，因为它们接受 slash 命令。

## Alternatives considered

- 只在可见的 `Picker` 里循环、让行内菜单继续截断被否决：一条 `cycle` 规则让"菜单会循环"成为单一而可预期的承诺，而不是逐个界面的偶然行为。
- 让单选题的数字只移动高亮被否决：需求要的是直接选择，设计也已经把数字当作答案。
- 让多选题的数字提交单标签答案被否决：这会把多选的第一个数字变成提前提交。
- 文本到达不读文本的菜单时关闭面板被否决，那是需求的反面；停用输入框把按键留在菜单里，并用变暗的提示符说明这件事。
- 启动选择器也停用输入框被否决：README 记录了选择器里可用 slash 命令，而这些界面没有别的办法敲出一条命令。

## Consequences

`tests/ui/app.test.tsx` 覆盖选择器循环、`@` 列表循环、穿过输入行的提问环循环、审批数字直接作答（含 `Stop turn` 取消而不提交结果）、单选数字直接作答、`Other answer` 不带编号、记录列表循环与停用输入框；`tests/ui/loop-form.test.tsx` 覆盖表单循环。`tests/expected/approval-options.txt` 记录了新的 `1–3 answer · ↑ ↓ select · Enter confirm` 页脚。README 双语对与 `tui-design.md` 的 2.5、4.3 节描述了该行为，实现与设计现在一致地把数字视为作答。
