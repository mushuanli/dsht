# Agent Note: 独立 HTTP 终端客户端

Status: implemented

## Problem

终端用户需要选择服务端已有的工作区和会话，同时避免启动额外的代理进程，或让客户端依赖 Harness 工作区内的包。

## Decision

本仓库提供 Node.js/Ink 可执行入口和可复用 HTTP 客户端。npm 包携带编译后的 JavaScript 和类型声明；唯一的 `dsht` bin 使 `npx @itookit/dsht` 无需源码仓库或 TypeScript loader 即可运行。发布名称为 `@itookit/dsht`，即 DeepSeek Harness Terminal：npm 会以「与 `dot`、`st` 等现有短名过于相似」为由拒绝非 scope 的 `dsht`，而 `dsh-tui` 的包名与 bin 已被另一个 Harness 终端客户端占用，沿用该名称会在全局安装时冲突。可执行命令保留短名 `dsht`，本地认证、价格和用量数据位于 `dsht` 目录，并可由 `DSHT_*` 覆盖。打包冒烟检查在仓库外执行 tarball，先验证再发布。发布的元数据记录作者、MIT 许可证、仓库地址和非 scope 公开访问权限，两份 README 也直接写明这些字段，不再把包名和许可证留给发布者决定。打包集合增加 README 截图和许可证文件，使相对路径图片在 registry 页面上可正常显示；冒烟检查断言这两个路径，并继续拒绝声明集合之外的任何打包文件。`/ws` 始终选择工作区，`/s` 选择当前工作区的会话，`/s all` 显式扩大列表范围。没有工作区时，`/s` 先引导选择工作区，而不改变 `/ws` 的含义。服务端仍单独启动。工作区列表读取 mux 首个 baseline；会话列表使用一元端点。每个请求显式保留服务端形参名称。重连替换 baseline 状态，不重放用户的修改请求。旧版服务端以 `chunks` 包装 `chunkrow/*` 事件，并省略进程内助手 baseline。读取器保留压缩记录的起始序号用于翻页，并汇总日志中未完成的尝试以显示实时输出；已提交的助手消息仍是对话依据。假设所有包装都是 `event` 会拒绝这些服务端，而丢弃压缩记录会丢失实时文本和翻页位置。

版本发布由 `publish.yml` 工作流在版本 tag 上完成，使用 trusted publishing（OIDC）并生成 provenance，不保存发布 token，这也在 npm 收紧 2FA-bypass token 时保持发布路径可用。Trusted publishing 无法创建包，因此首个版本仍由人工带 `--otp` 发布，之后所有版本交给该工作流；它还会拒绝与 `package.json` 不一致的 tag，手动触发时只打包不发布。

文件补全调用服务端 `fileReferences/list`，并保留仅含路径的 `@` 提示词文本。读取本地字节或展开文件内容会改变 Harness 语义，并为远程用户选择错误的文件系统。独立适配层维护服务端引用语法，不导入 Harness 包。输入框自行管理光标和本地剪除缓冲区，因为不公开光标的输入组件无法支持所需控制键编辑；Ink 解码终端按键，Intl.Segmenter 提供组合字符边界。补全仅在输入末尾激活；过期搜索会取消，迟到结果会忽略。Esc 优先关闭补全菜单，再用于取消任务。

终端依据服务端运行状态通知处理中断，不从流式文本推断活动。Ctrl+C 先清空非空输入，再取消所选轮次或允许空闲退出；所有退出路径都在关闭连接前停止该轮次，因为「客户端已退出但服务端仍在运行」正是用户报告的困惑；会话空闲时不发送多余取消。工具参数和结果保留在服务端历史中；终端行仅展示描述或命令／路径／查询摘要，并隐藏结果正文。思考是单行规则在流式期间的例外：实时尝试保留完整文本，因为用户正在观察它逐步生成；消息提交后折叠为一行，可用 `/think` 再次展开；消息始终保留完整文本，因此折叠不会缩小搜索或选择器的范围。状态图标替代纯工具行的角色标题，摘要按终端显示宽度截断。完整调用 ID 将交错返回的结果关联到对应操作说明。状态指标使用完整日志的控制流投影，通过每个键的序号检查防止迟到的 follow 快照覆盖新值；只累加已加载窗口会低估用量。上下文压力保持近似标记，本地观察到的运行起点会明确标注，不冒充持久时间戳。

Ink 6 将终端 DEL 和 CSI 3~ 都标为 delete；输入适配器观察 Ink 的原始输入事件，区分向后擦除和向前删除，同时支持 Meta-DEL 及 Kitty 退格。输入期间按对话对象、版本和终端宽度复用已换行的历史，状态栏另行跟随控制器更新。Follow 帧和历史翻页都会递增版本，确保缓存不会隐藏新历史。组合字符按需查找，普通字符输入不会把整段草稿展开成分段数组。本地 500 条合成消息基准中，30 次按键在复用前读取历史 30 次，复用后为零；输入／渲染中位耗时从 375.33 ms 降至 6.01 ms（p95 为 400.03 / 8.55 ms）。这些测量排除网络和模型耗时，不作为跨机器 CI 阈值。

应用测试渲染不带样式的帧，因为断言和 `tests/expected/` 中的预期输出描述的是文本。从终端启动的测试运行器会向每个测试文件导出 `FORCE_COLOR=1`，使 Ink 在提示符与其后文本之间插入 SGR 转义序列，同一帧在管道中与在终端里是不同的字符串；在 Ink 加载前固定颜色等级可使两者一致，并让录制的预期输出继续适用。`test:terminal` 在该强制着色环境下重跑测试，`prepublishOnly` 采用这次运行，因此从终端发布时验证的是终端自身造成的环境，而不只是代理或 CI 运行器提供的管道环境。

历史导航复用缓存的对话布局及记录序号到终端行的映射。保留事件增量折叠，并按变更事件复用其投影和换行结果：此前每个流式分片都重算整个对话，使按键需要在对话布局上排队；合成 500 条消息的历史每帧耗时 349ms，加入缓存后为 0.6ms。SGR 鼠标报文与输入框文本分开处理；向上滚动按保留的历史截点翻页，新输出保留阅读位置。显式跳转及当前会话搜索可取消地补齐旧页，并拒绝没有推进的分页。跨会话搜索使用有数量限制的 HTTP 搜索接口；接口没有工作区筛选参数或继续游标，因此工作区筛选保留全局截断标记。选择会话后通过历史定位匹配记录序号，不读取服务端配置或持久化文件。

计费使用持久化的逐次请求用量，不对累计遥测基线做差。完整 HTTP 历史扫描保留请求模型及结算时间，替换重复采样、单独统计重试并排除 fork 继承事件。价格版本使用不重叠的显式有效期和本地高峰时间表，每次扫描都按当前配置重新计算已缓存费用，因此修正后的价目表会取代先前扫描套用的费率，而不会继续信任已被取代的版本。按用户要求，DeepSeek 官方供应商的模型名包含 pro 时归为 Pro，其余归为 Flash，精确模型配置优先于此规则。按 origin 隔离的本地账本只保存用量与价格，不保存对话正文。无法归属的用量保留未计价数量，扫描失败保留部分总额；显示金额是人民币估算，不是账户账单。官方费率按模型逐条记录，而不是从另一个模型推导，因为把 Flash 当作 Pro 的三分之一会高估官方 Flash 价目；内置表现在显式保存两个模型，并记录供应方公告的 2026-09-14 将 `deepseek-v4-pro` 交由 Flash 计费的变更。缺少结算时间戳的请求按该模型族最低费率计价并单独计为估算值，而不是从总额中消失；未列出的供应商保持未计价，不套用官方价目。每个会话的逐条请求会落盘，而跳过标记只存在内存中，因此重启后的首次扫描会重读每个会话，并按各请求自身的结算时间重算客户端缺席期间的费用。每个会话单独读取，因此某个会话被拒绝或不可达不会冻结其余会话的费率；子代理会话通过其持久父级寻址，列表未提供的投递模式用另一种形式重试解析。

覆盖状态属于账本而非渲染层：之前运行缓存的费用视为完整，因此重启不会再把自己完整的数据说成不完整，只有账本为空或扫描失败才算不完整。状态栏复用既有的 `!` 前缀通报该状态，`/status` 说明原因，于是 `*` 只剩一个含义——该小计本身不精确。

对话标题依次取实时标题投影、会话列表标题和 ID。显式 Esc 取消绕过缓存运行状态的判断，复用正在提交的取消请求，并在收到空闲通知前跨历史更新保留取消回执。打开的菜单关闭时同时取消已知正在运行的任务；本地导航或费用加载保留取消优先级。

Slash 命令面板是临时的：执行下一条命令会关闭上一条命令打开的面板，否则由十秒计时器关闭。此前 `/help`、`/cost`、`/status` 会一直留在屏幕上直到再次执行同一命令，导致旧输出与当前视图混在一起；用生存期解决，无需新增关闭按键。该生存期通过 prop 注入，使测试以毫秒级观察而不必等待生产值。

启动配置接受 `dsh web` 打印的地址，其中以 `?token=` 查询参数携带启动 token。在校验前拆出该参数，用户即可把打印出的整行原样用作 `DSH_URL`；其他路径或查询参数仍会失败，使 origin 对 cookie 与费用归集保持明确。`DSH_TOKEN` 优先于 URL 中的参数，空值不参与认证，token 仅存在于内存：只有兑换得到的 cookie 会落盘。

两份 README 保持逐行配对：每个标题、段落、列表项、表格行和围栏代码块在两边占据相同的物理行，`README.i18n.yaml` 记录复核后的哈希。因此翻译改动会在两个文件的同一处修改，并且表格行之间绝不插入空行——否则 GitHub 与 npm 都不会把它渲染成表格。

## Alternatives considered

复用 Cordis 客户端服务会使安装和启动依赖 Harness 组合。Rust 改善原生分发，但需要更多协议和终端集成工作。Python 引入了所选 Node.js 实现不需要的另一套运行时生态。独立 Git 仓库使依赖安装和发布历史保持独立。

## Consequences

适配层必须跟踪服务端非稳定报文的变化。CLI 通过仅限所有者访问的原子文件持久保存按 origin 隔离的 cookie，复用前验证缓存认证，仅在提供启动 token 时刷新被拒绝的凭据。启动 token 仅留在内存。Slash 选择器先匹配完整身份或名称，再匹配唯一 ID 前缀，并拒绝有歧义的目标。未知 waterfall 委托后续处理，不阻塞服务端。测试覆盖本地 HTTP/WS 传输、用户选择、命令子进程及录制对话投影，不声称覆盖真实模型供应商。本独立仓库没有被本决策取代的已有记录。
