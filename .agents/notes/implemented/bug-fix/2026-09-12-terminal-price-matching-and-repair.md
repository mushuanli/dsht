# Agent Note: The ledger prices what the table declares, and only an amount is final

Status: implemented

## Problem

A model name was priced by asking whether it contained the substring `pro`: an official name the table did not list silently took Flash rates, and a Flash name that happened to contain those letters — `deepseek-v4-flash-prod`, `deepseek-proxy-*` — took Pro rates, which are about four and a half times higher. The host reports names that differ from the published table by case, surrounding space, a `-expires-on-0910` suffix, and even the CJK full stop a display path can substitute for a period, so an exact match alone would have priced almost nothing. Two further decisions hid rather than reported what the host had recorded: a request with no settlement time took the cheapest off-peak rate as a floor, which entered the lifetime total while staying out of every day range, so the day subtotals did not add up to it, and a cache-write bucket the published DeepSeek table does not price was billed at the cache-miss input rate, which is a rate nobody published. Finally, an unpriced request was final: a table that later covered its model could not price it without `--reprice`.

Three defects in the same area were found while reviewing this, none of them visible in the numbers: a compaction's summary request — the largest single request in a session, since it reads the whole context — reports its own provider, model and usage on `compaction/summary` instead of appearing as an assistant message, so a fold that ignored that event never billed it; `loadLedgers` deleted any file it could not parse, which silently re-priced that session's sealed amounts under today's table; and the rate table's own identity said nothing about the rates, so a corrected file that kept its ids kept charging superseded rates.

## Decision

A price version declares the names it covers. Matching is exact on the canonical name first, then against the declared aliases with a trailing `*` as a prefix, and a name the table does not declare stays `no price version` — guessing a rate is indistinguishable from a wrong one. Canonicalization is NFKC plus an explicit map for the CJK stops NFKC does not fold. The shipped Flash version therefore lists the superseded names the published table keeps callable, and the Pro version lists only `deepseek-v4-pro*` and `deepseek-v4.1-pro*`: a `deepseek-pro*` alias was written first and dropped when a test showed it claiming `deepseek-proxy-*`, because a prefix alias is exactly as dangerous as the substring rule it replaced.

Only an amount is final. A charge with no amount is re-decided on every scan, so a table that later covers its model, or a table that was wrong, prices it without a repair; `--reprice` remains the only way to move an amount that was already recorded. A request with no settlement time is `missing time` rather than a floor amount, which removes the estimated bucket and makes the day subtotals add up to the lifetime total. A cache-write bucket on the published DeepSeek table is `unsupported usage` rather than a rate dsht invented. Every amount records the rule that matched, the engine version, and a digest of the price version itself, so an audit can tell which charges an older engine sealed and which rates it used.

`compaction/summary` is billed from its own provider, model and usage, and a summary with no usage — an unmarked template summarizer, which makes no provider call — is not a request at all. A ledger file this build cannot read is set aside under a `.unreadable` name and counted rather than deleted, because deleting it destroys the only copy of amounts the host log cannot reproduce.

## Alternatives considered

Word-boundary matching on `pro` was rejected as a smaller version of the same guess: it would still price an unlisted official model as Flash. Matching only exact names was rejected because the host's suffixed and re-punctuated names would all go unpriced, which is how the ledger reached 5,310 unpriced requests before. Keeping the estimated floor was rejected because a peak band differs from its off-peak half by a factor of two, so the floor is wrong in one of the two cases and cannot be reported as a subtotal. Re-pricing silently when the table changes was rejected earlier and again here: unpriced requests now price themselves, and a recorded amount still moves only when asked. Deleting an unreadable ledger file was rejected because a corrupt file is exactly when the decisions are least reproducible.

## Consequences

`tests/cost/cost.test.ts` covers exact, alias and prefix matching, canonicalization including the CJK stop and case, that a name containing `pro` inside another word is not Pro, that an undeclared name is unpriced, the recorded rule, engine and rate digest with a digest that changes when a rate is edited under the same id, cache-write refusal, `missing time` leaving the day subtotals equal to the lifetime total, a summary billed from its own route, an unpriced request pricing itself once a table covers it while a priced one waits for `--reprice`, and the interval and retry folds. `tests/cost/ledger-files.test.ts` covers that an unreadable ledger keeps its bytes under a name the loader never reads again. The shipped table's rates are unchanged by this note; what changed is how a model name reaches them.
