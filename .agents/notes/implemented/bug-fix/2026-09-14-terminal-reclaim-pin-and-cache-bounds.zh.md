# Agent Note：回收保护会解除，两个提示词存储都守住预算

Status: implemented

## Problem

在审查会话容器的内存占用时，发现有三处"写进了文档却没有真正执行"的界限。

`SessionController.older` 只要扩展了实时记录就会把 `view.pinned` 置位。这个置位没有自己的清除边：只有 UI 派生出的 `pinHistory` 调用能清它，而那个 effect 只在视口位置或打开的面板变化时运行。因此，读者只要从实时末端取过一页——在边界回填一步、`/older`、或 `/think` 加载更早的思考——transcript 就会**永久**处于保护状态：此后每一帧 `reclaimHistory` 都返回 0，2,000 条 / 16 MiB 的预算静默失效，而每多取一页都在继续加记录。

`adoptCachedPrompts` 从进程级 `PromptCache` 播种索引后直接 `markComplete()`，却没有 `settle()`。缓存命中是唯一跳过索引预算的路径，于是选中会话可能在索引与缓存里各留一份完整列表，同时还声称自己已穷尽。

`PromptCache.put` 只按会话整体淘汰，并且总保留至少一个条目。单个会话的提示词文本超过整份预算时会被完整存下并保留，因为淘汰在一个条目上就停了。

## Decision

`older` 不再置位。凡是必须存活的东西都由视口覆盖：往回滚动会设置滚动位置、`/think` 会打开面板、为回填取的那一页在调用 resolve 之前就已经把提示词折进索引。其余内容按构造即可重载——`trimHistory` 会推进重载截止点并保持 `hasMore` 为真——所以去掉这个置位不会让读者看到任何变化，却把预算还了回来。

`adoptCachedPrompts` 现在与它所替代的回填完全一致：先 `settle()` 索引再标记完成；`markComplete` 本来就会拒绝丢弃过前缀的索引，因此被丢弃的部分仍可由惰性回退路径取回。

`PromptCache.put` 会把单个超大会话截断到预算内最新的那些提示词，并记为不完整，因此后续打开仍会去取更早的部分，而不是信任一份前端有洞的列表。`drop`——写好却从未接线的那一个调用——现在在 `/compact` 成功后执行，因为压缩会重写缓存提示词所来自的宿主日志。

## Alternatives considered

保留强制置位、再给它一个清除边（例如下一次折叠时清除）被否决：这个置位唯一的理由是取回的那一页，而那一页要么已经折进索引、要么已被视口保护，所以这份多出来的状态已无事可做。按"整体丢弃超大会话"来限制缓存也被否决：长会话将永远不被缓存、每次打开都要重走一遍，而那正是缓存要消除的成本。

## Consequences

`tests/session/memory.test.ts` 固定"翻历史后 `view.pinned` 仍为 false，且后续帧照常回收"。`tests/session/info.test.ts` 覆盖超大条目的截断与它的不完整标记。`tui-design.md` 的 5.7.3 / 5.7.4 / 5.7.5 / 5.7.7 记录了单一写入者与守住预算的播种。没有用户可见行为变化，因此 README 双语未改。
