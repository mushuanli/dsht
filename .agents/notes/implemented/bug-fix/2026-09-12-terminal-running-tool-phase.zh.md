# Agent Note: 状态栏会说出正在执行的工具，暂停时也一样

Status: implemented

## Problem

长命令运行时，状态栏关于它什么都不显示。阶段——工具名与它的时长——过去由助手流推导，而它只在流还在发送增量期间存在：宿主在助手消息提交时结束该流，之后才运行工具，因此阶段恰好在这个最有意思的部分开始时已被清除。于是状态栏只能在模型花几秒写这次调用的期间说出工具名。第二个缺陷在状态栏的另一种状态下藏起了同样的信息：暂停的状态栏会整组丢弃阶段，因此为复制文本而选中内容的用户——这个动作会打开复制模式——只看到 `⏸ copy`，得不到"客户端正在做什么"的答案，也无法区分暂停的时钟与卡死。

## Decision

Transcript 通过读取**当前打开回合中未被回答的工具调用**来回答"正在运行什么"。宿主的 `tool/call` 事件不被保留（内存里只保留用户可见内容），所以这次调用从携带 tool-call 块的助手消息、以及回答它的结果中读出；没有对应结果的调用就是正在执行的那个，而等待最久的未回答调用就是最先开始的那个。它的时长从该消息的时间起算——保留步骤现在会为每个可见事件保留这个时间：每个事件一个数字，就是"能说出任何事发生在何时"的代价。

`livePhase` 在助手仍在书写时返回流式阶段，流结束后落到正在运行的工具，因此所有消费方共用同一个定义。暂停的状态栏保留阶段：暂停原因已经说明了时钟为何不动，而丢掉正在运行的工具则删掉了这个状态栏存在的唯一理由。

## Alternatives considered

保留宿主的 `tool/call` 事件被否决：它携带工具的原始参数，对于 shell 命令或文件写入，那正是保留策略要把它们挡在客户端内存之外的载荷。用回合开始时间给工具计时被否决，因为那是把整个回合的时长当作命令的时长上报。在客户端记录到达时间被否决，因为它发明了第二个时钟，而且对从历史加载的事件会算错。继续只显示流式阶段被否决，因为长命令正是人们读状态栏的场景。

## Consequences

`tests/session/transcript.test.ts` 覆盖一个在飞的调用、两个调用且第一个已被回答、阶段随之移动，以及回合结束时仍有调用未回答——只有回合结束才能清除的取消场景。`tests/ui/app.test.tsx` 用正在运行的工具渲染状态栏并断言 `◐ 0:08 · bash 5s · ^C`，随后断言同一阶段在 `copy`、`dialog` 与 `history` 三种暂停下都保留在各自原因之后。没有打开回合、也没有流式阶段的状态栏仍然不显示阶段，而不是去猜。
