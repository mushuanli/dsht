# Agent Note: 种子价格文件跟随随包价目表

Status: implemented

## Problem

`prices.json` 首次发布的 Flash 费率是每百万输入 3 元、每百万缓存命中 0.1 元，一小时后随包默认值被改成官方公布的 2 元与 0.04 元。这个修正从未到达任何安装：`prices.json` 覆盖随包价目表，它以独占创建写出、此后永不替换，而账本在决定时就把金额封存，后来的价目表无法移动它。某用户的账本三天记录 ¥151.65，而按官方价目表是 ¥91.18；每一天的小计都按不同倍数偏离；同一文件里的第二个缺陷又叠加其上：被取代的文件只列了旧的模型别名，于是 5,310 个模型名报为后续别名的请求完全没有定价。总额恰好接近真实值，这正是两天都没人发现的原因。

## Decision

现在会记录种下的文件。`prices.seed.json` 保存一个版本号与工具写入字节的摘要，`loadPrices` 比较两者：只要文件仍然哈希到该记录，工具就拥有它，并用本次构建携带的价目表重写它；第一次编辑之后文件即为权威，用户选定的费率永不被覆盖。没有记录的文件早于该机制，因此只有与被取代的种子完全一致时才替换——其余都可能是手写的表。内容没有变化时不写入，因此未改动的配置完全不产生写操作，只读目录也能启动。

`CostLedger.reprice()` 依据每笔账记录的样本重新决定它，因为一笔账保留着当时用于决定的 provider、model、time 与 token；`--reprice` 用来运行它。这是对在错误价目表下封存金额的修复途径，也是修正后的表触达已记录金额的方式；没有终端时这次修复就是整个运行，并打印有多少笔账发生变化。

官方价目表也让 V4 Pro 在 2026-09-14 之后继续按自身费率计费，因此该区间保持开放，原先在那个日期之后把 Pro 记为 Flash 费的条目已删除。

## Alternatives considered

保持文件权威、让用户自己去改被否决，因为这个缺陷出自我们这边，而面板里没有任何地方说明费率来自文件。每次启动都刷新文件被否决，因为那会抹掉用户设定的费率。匹配到被取代的种子时删除文件被否决，因为该文件是阅读与修改费率的既定位置，重写它才能保持这一点。价目表一变就自动重算被否决，因为那会让已记录的金额取决于进程恰好在何时运行；修复仍是显式的开关，同时 `/cost` 现在会标明价目表来自用户文件，让错误的表可见而不是静默。

## Consequences

`tests/cost/config.test.ts` 覆盖首次种下、未编辑文件被刷新、已编辑文件被保留、被取代的种子被替换、无戳记的表不被改动、只读场景，以及重算结果会持久化且不触碰没有用量的请求。`tests/cost/cost.test.ts` 把费率钉在官方价目表上，包括那些仍必须能定价的被取代模型别名。2026-09-07 至 2026-09-09 早于 `from` 的请求保持无价并如实计数，因为没有官方费率覆盖它们，猜测比报告更糟。
